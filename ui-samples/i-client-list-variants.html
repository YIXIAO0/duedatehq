Client list — 4 layout variants

Same 6 clients, four different rendering approaches. The current production layout shows generic people icons + a stark "16 OPEN" red number — these variants explore richer per-row information (next deadline, entity type, state, urgency) and different density / scan strategies.

I1 · Refined list (closest to current, much richer)

Initials avatar (colored per client) replaces the identical-looking generic people icon. Right column carries next deadline date + days-until (with urgency color) — far more useful than just "16 OPEN". Entity type and state as small inline chips next to the name. The same row height as today but with 3× the per-client information.

I3 · Card grid (visual scan, less list-y)

2-column grid of mini cards. Each card carries the next-deadline pill prominently, with avatar + name + entity at the top. Less scanning effort per client (full card content is in your eye-line) but harder to compare across many clients quickly. Best for ~10-30 client books where browsing is easier than searching.

I4 · Urgency-bucketed sections (action-first, default sort)

Splits the same list into "Action needed" (next deadline ≤7d), "This month" (≤30d), and "On track". The CPA's working set sits at the top by default. Tradeoffs: alphabetical scan is harder; needs a filter/search bar above to recover that. Best when the user mostly cares about what's about to break, not everyone in the book.

My picks:

I1 — safest upgrade. Same row shape as today, three times the info per row.

I2 — the right call once book size grows past ~30. Drake / desktop-tax-software DNA.

I3 — most "designed", but doesn't scale to 50+ clients. Fine for a small practitioner.

I4 — strongest workflow alignment ("show me what's on fire"). Riskier because alphabetical scan goes away — needs a search bar above to compensate.

If forced to pick one: I1 for now (lowest disruption, biggest information gain), then revisit I2 once you have users with 30+ client books.
