Sub-timeline · 4 design directions

每条 deadline 内嵌一条横轴：左 = 今天，右 = due date，中间节点用户自己加， 每个节点带 mini due date。下面是 4 个方向，配真实示例数据 （Rodriguez & Associates · Form 1120 公司税申报 · due Jun 15）。

+ 优点：节点间距=真实时间间距，CPA 一眼看到"接下来 20 天没事，然后突然集中冲刺"。 Today 永远在最左，deadline 永远在最右，视觉锚点稳定。
− 风险：节点 5+ 个且时间挤在一起时 label 会重叠。需要做"hover 才显示完整 label / 否则截断"或"小屏切换成下面 B 的等距 stepper"的兜底。
+ 加节点交互：右上角 "+ Add stage" 弹小表单（label + date），或 hover 在轴上空白处出现细 + 号 cursor。

+ 优点：永远不会重叠，节点多少都好看。最熟悉的视觉模式。

C · Rail + cards (info-rich)

上面 A 的轴 + 下面每个 stage 一张 mini-card（owner 头像、备注 chip、状态切换）。 适合多人协作场景 — Joycee 那种 2-10 人小所，stage owner 不一定是 deadline owner。

A/B/C 都太大放不进 dashboard 列表。这个是给 dashboard "deadline 折叠行"用的小总结。 点进详情页才看完整 timeline。

Calendar 单向 — 我建议这样

你问怎么设计最专业。核心原则是 deadline 是公开 commitment（IRS / 客户预期），sub-stage 是内部 prep work。 两者不一样，不应该塞进同一个 calendar 视图。

✓ 进 calendar / ICS
  • ✓ Deadline 本身（一条 ddl = 一个 event）
  • ✓ Extension 后的新 due date
  • ✓ ICS 订阅 / Google / Outlook OAuth
✗ 不进 calendar
  • ✗ Sub-stage 节点（内部 prep，会污染日历）
  • ✗ Stage 提醒 → 走 in-app banner / email digest
  • ✗ 已完成 stage（噪音）
Sub-stage 怎么提醒（不靠 calendar）
  • · Dashboard banner：当天 / 明天到期的 stage 顶部置顶
  • · Weekly email digest：周一发本周 stages（跟 deadline digest 一封信里分两个 section）
  • · Deadline 详情页：next-up stage 高亮 + days-until 倒计时
  • · Sidebar badge：overdue stage 数量（跟 Tax updates badge 同款）
为什么这样最专业：CPA 自己的 Google Calendar 已经被会议塞满了。 如果我们把 prep stages 也推进去，他每天看到 6 个"DueDateHQ 提醒"会直接关订阅。 ICS = 客户/IRS 视角的"对外承诺"，stages = 内部 to-do，分开就不会冲突。

需要你决定的

  1. Timeline 视觉：A（按时间比例）/ B（等距 stepper）/ C（A 加下方 cards）/ D（dashboard 一行小总结，可选）
  2. 详情页用：默认就铺开，还是默认 collapse 只显示 rail
  3. Dashboard 行：用 D 的 progress bar，还是先不动等 deadline-only 视觉
  4. Calendar 策略：上面的方案 OK 吗？deadline-only ICS + stages 走 banner/email
  5. 每个 stage 的 owner：开放（C 显示头像）还是只用 deadline 总 owner（A/B 不显示）
